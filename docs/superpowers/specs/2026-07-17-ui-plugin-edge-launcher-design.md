# 左侧 UI 插件边缘入口设计

> 日期：2026-07-17  
> 状态：已确认，待编写实施计划  
> 范围：让现有 UI 插件更容易发现和打开，同时保持 DriFox 当前紧凑消息流的视觉与布局

## 1. 背景与目标

DriFox 当前的 UI 插件主要通过斜杠命令打开，例如 `/file-tree`、`/plugin-marketplace` 和 `/context-usage-stats`。这种方式对熟悉命令的用户有效，但插件入口不够容易发现。直接增加固定侧边栏又会侵入当前界面：消息流会变窄，视觉上也与现有紧凑、粉色强调的 UI 不一致。

本设计增加一个左侧边缘入口：

- 默认只显示约 4px 的细线；
- 鼠标靠近左边缘时，细线展开为小胶囊；
- 点击小胶囊后，插件菜单向右展开；
- 点击菜单项后，复用现有 UIPluginRegistry 和 CardManager 打开插件卡片；
- 不改变消息区宽度，不新增常驻侧栏，不替换现有命令入口。

## 2. 已确认的交互

### 2.1 状态流

```text
默认状态：4px 左侧细线
      ↓ 鼠标进入左侧触发区域
靠近状态：展开为小胶囊
      ↓ 点击小胶囊
菜单状态：菜单向右展开
      ↓ 点击插件项
打开/切换对应浮动卡片
```

### 2.2 默认状态

- 入口固定在主窗口消息区域左侧中部；
- 可见部分约 4px 宽，使用当前主题的强调色；
- 入口是浮层子控件，不加入现有布局；
- 不挤压 `chat_scroll_area`、输入区或顶部/底部卡片容器。

### 2.3 靠近状态

- 左侧约 20px 的透明区域作为鼠标触发区域；
- 鼠标进入后，细线平滑展开为约 `18px × 60px` 的小胶囊；
- 胶囊只显示插件入口图标，不显示文字；
- 鼠标离开后延迟收起，避免鼠标经过边缘时闪烁；
- 菜单未打开时，胶囊离开后恢复细线。

### 2.4 菜单状态

- 菜单只通过点击胶囊打开，不因悬停自动打开；
- 菜单从胶囊右侧向右展开，不覆盖消息内容的主要区域；
- 菜单打开期间，胶囊保持展开；
- 点击菜单项打开或切换对应浮动卡片；
- 点击空白处或按 `Esc` 关闭菜单并恢复细线；
- UI 插件热重载或卸载时，菜单关闭并重新读取插件列表。

## 3. 技术架构

### 3.1 新增组件

新增 `app/widgets/ui_plugin_edge_launcher.py`，包含一个独立的 `UIPluginEdgeLauncher(QWidget)` 组件。

组件职责限制为：

1. 绘制细线和小胶囊；
2. 管理靠近、离开、点击、收起等交互状态；
3. 创建和显示插件菜单；
4. 把菜单点击转发给 UIPluginRegistry。

组件不负责：

- 创建插件卡片实例；
- 管理插件启用/禁用状态；
- 执行插件安装、卸载；
- 维护独立的插件注册表；
- 替换现有的命令系统或 CardManager。

### 3.2 与 UIPluginRegistry 的连接

Launcher 每次显示菜单时读取：

```python
UIPluginRegistry.get_instance().get_floating_cards()
```

每个 `FloatingCardInfo` 生成一个菜单项，使用以下信息：

- `card_id`：打开卡片时使用；
- `title`：菜单显示标题；
- `plugin_name`：必要时用于辅助标识；
- `metadata`：本次不参与菜单渲染，保留现有字段兼容性；

UIPluginRegistry 增加公开的窗口级调用入口：

```python
registry.toggle_floating_card(card_id, main_widget)
```

该入口只复用当前 `_show_floating_card()` 的行为，不改变既有卡片创建、缓存、互斥和关闭逻辑。已有斜杠命令继续调用现有处理器。

### 3.3 与 MainWidget 的连接

在 `MainWidget.setup_ui()` 中创建 Launcher，但不将其加入 `QVBoxLayout`：

```text
MainWidget
├── 现有 QVBoxLayout
│   ├── 顶部卡片容器
│   ├── 消息滚动区
│   └── 底部卡片容器
└── UIPluginEdgeLauncher（浮层子控件）
```

Launcher 作为 `MainWidget` 的子控件，通过窗口尺寸变化重新定位到消息区域左侧中部，并在需要时调用 `raise_()` 保证入口位于消息内容之上。

插件加载完成后调用 `refresh_plugins()`。菜单不提前创建插件项，而是在打开时读取最新注册表，减少热重载后的状态同步问题。

### 3.4 多窗口隔离

- 每个 `MainWidget` 创建自己的 Launcher；
- Launcher 不保存全局窗口引用；
- 点击菜单项时显式传入当前 `main_widget`；
- UIPluginRegistry 继续使用现有的 `window_id` 和每窗口卡片实例缓存；
- 不通过单例 `_main_widget` 决定目标窗口。

## 4. 主题、布局与性能

### 4.1 主题

- 入口、菜单背景、边框、文字颜色从现有主题/设计令牌读取；
- 不硬编码当前截图中的粉色作为唯一颜色；
- 支持亮色和暗色主题；
- 主题刷新时更新细线、胶囊和菜单样式。

### 4.2 布局

- Launcher 是浮层，不参与主布局尺寸计算；
- 左侧透明触发区域只接收鼠标事件，不绘制大面积背景；
- 菜单使用相对窗口定位，不依赖固定屏幕坐标；
- 菜单超出窗口底部时，向上调整位置；
- 不影响聊天滚动条和输入区交互。

### 4.3 性能

- 每个主窗口只创建一个 Launcher；
- 不使用轮询检测鼠标位置，仅使用 Qt 鼠标进入/离开事件；
- 菜单项按需创建；
- 不为每个插件创建额外线程或 WebEngine；
- 不重复创建浮动卡片，继续使用 UIPluginRegistry 的每窗口缓存。

## 5. 异常与边界处理

- 没有可用 UI 插件时隐藏整个入口；
- 单个 `FloatingCardInfo` 数据异常时跳过该项，其他插件继续显示；
- 卡片创建或切换失败时捕获异常并记录 warning，不让主窗口崩溃；
- 插件热卸载时关闭菜单并刷新列表，避免残留失效菜单项；
- 主窗口销毁时关闭菜单、停止延迟收起计时器并解除事件过滤器；
- 主题读取失败时使用安全回退色；
- 所有几何计算使用 Qt 的窗口/控件坐标转换，兼容高 DPI；
- 如果菜单被系统卡片遮挡，仍保留现有斜杠命令作为备用入口。

## 6. 测试设计

新增 `tests/widgets/test_ui_plugin_edge_launcher.py`，覆盖以下行为：

### 6.1 Launcher 状态

- 初始状态显示细线、菜单隐藏；
- 鼠标进入触发区域后展开胶囊；
- 鼠标离开后按延迟收起；
- 菜单打开期间离开手柄不会立即收起；
- 点击空白和按 `Esc` 会关闭菜单。

### 6.2 菜单与注册表

- 菜单项目来自 `get_floating_cards()`；
- 没有插件时入口隐藏；
- 点击菜单项调用当前窗口的卡片切换接口；
- 插件热重载后再次打开菜单能看到最新列表；
- 插件卸载后菜单不会保留失效项目。

### 6.3 多窗口与布局

- 两个 `MainWidget` 的 Launcher 相互独立；
- 点击窗口 A 的菜单项不会打开窗口 B 的卡片；
- Launcher 不改变主布局的 `sizeHint` 和消息区宽度；
- 窗口尺寸变化后入口仍位于消息区左侧中部。

### 6.4 手动验收

- 左侧默认只看到细线；
- 鼠标靠近后细线展开为小胶囊；
- 点击胶囊后菜单向右展开；
- 菜单不遮挡关键消息内容；
- 文件树、插件市场、统计、系统清理等入口可正常打开；
- 卡片关闭后输入区状态正常恢复；
- 亮色/暗色主题下入口颜色正确；
- 第二个窗口的入口和卡片不互相影响；
- 原有 `/file-tree`、`/plugin-marketplace` 等命令仍可用。

## 7. 文件范围

### 新增文件

- `app/widgets/ui_plugin_edge_launcher.py`
- `tests/widgets/test_ui_plugin_edge_launcher.py`
- `docs/superpowers/specs/2026-07-17-ui-plugin-edge-launcher-design.md`

### 修改文件

- `app/main_widget.py`：创建 Launcher、定位浮层、插件加载完成后刷新；
- `app/core/ui_plugin_registry.py`：增加公开的当前窗口卡片切换入口；
- `plugins/system/README.md`：说明 UI 插件可通过左侧入口或斜杠命令打开。

### 明确不改

- `app/widgets/cards/card_manager.py` 的卡片布局和互斥规则；
- 各个现有 UI 插件的卡片实现；
- `/file-tree`、`/plugin-marketplace` 等现有命令；
- 插件安装、启用、禁用和热重载机制；
- CI 配置、锁文件和与本任务无关的未提交文件。

## 8. 非目标

本次不实现：

- 用户自定义入口位置；
- 拖动或固定 Launcher；
- 插件分组、收藏、最近使用排序；
- 插件图标元数据协议；
- 独立的插件设置页；
- 移动端或网关 UI 的入口同步。

这些功能可以在后续真实使用反馈证明有必要后再单独设计。

## 9. 成功标准

满足以下条件即视为完成：

1. 用户无需记忆命令即可发现并打开已安装 UI 插件；
2. 默认状态几乎不侵入当前界面；
3. 消息区宽度、输入区布局和现有浮动卡片行为不变；
4. 多窗口、主题切换、插件热重载和卡片关闭状态不回归；
5. 原有斜杠命令继续可用；
6. 自动化测试覆盖 Launcher 状态、菜单、注册表调用和多窗口隔离。
