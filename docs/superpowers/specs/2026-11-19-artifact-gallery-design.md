# 消息成果栏：轻量文件列表与单行画廊

日期：2026-11-19 · 方案：A2 单行版（布局已确认）

## 目标与范围

成果栏在消息里形成一个独立但不过分抢眼的内容区。折叠时看图片和数量，展开后找文件。只改 `plugins/artifacts-manager/ui/artifact_panel.py` 和对应的 `tests/plugins/test_artifacts_manager.py`；保留现有文件类别判定、轮次归属、工具契约和历史恢复，不改宿主滚动逻辑。

## 折叠态：单行画廊

- 标题左侧为「成果」，右侧常驻总数与展开入口。主题决定边框、底色和次级文字色，标题、画廊和摘要共享一个浅底容器与统一内边距。
- 图片同高、左对齐、不换行。首图略宽，其余为常规缩略图；单图也按首图宽度上限展示，不拉满栏。以约 64 逻辑像素高为起点，按比例完整显示，空白用主题底色填充，不裁切图表文字。
- 最多显示前三张；窄栏优先减少常规缩略图数量，并保证剩余图片计数可见。隐藏图片用 `+N` 表示（只计图片），点击进入完整列表。极窄时允许首图缩窄；若首图与 `+N` 都无法合理放置，则只显示图片计数入口。折叠态不使用横向滚动条。
- 混合成果时，在画廊下用一行次级文字显示「另有 N 个文件」（非图片计数）；纯文件成果只显示标题和总数，无图片占位；空成果仍整区隐藏。
- 缩略图继续单击预览、拖拽导出；文件缺失或无法解码时保留同尺寸占位，不改变布局。首次显示与宽度切换都按实际可用宽度计算；仅可见项变化时更新可见缩略图，不因每个像素的宽度变化重复解码。

## 展开态：轻量文件列表

- 隐藏折叠画廊与摘要，展示原顺序的完整类型混合列表，沿用现有的「还有 N 项」入口。列表列宽对齐，文件名优先占用可用宽度，以省略号和提示保留长名的可读性。
- 文件使用清晰的扩展名徽标或通用文件标记，元数据用弱色显示人可读类型、大小等信息；图片仍使用真实缩略图，视频仍用封面占位。用轻分隔和悬停态区分条目，不给每行叠厚边框。
- 行尾保留「打开所在文件夹」入口，图标与提示须和动作一致。原有打开、预览、拖拽和右键行为不变。

## 验收

- 人工检查浅色、深色和窄栏：空、纯文件、单图、多图与混合成果；图表没有裁边；缩略图固定单行；`+N` 与非图片摘要计数准确。
- 测试覆盖缩略图数量随宽度变化、`+N` 展开、折叠与列表互斥、文本徽标、SVG 与普通图片预览、缺失图片占位。原成果栏测试保持通过。
- 保留分帧解码和有界缓存；折叠态与展开态若请求不同缩略图尺寸，缓存须区分尺寸，不能把小图拉大或在窗口宽度变化时缓存无界增长。继续使用现有 `heightChanged` 契约，不用额外滚动容器或宿主补偿。
