## 一、实施台账（2026-11-19 性能批）

### 2026-11-28 工具结果与会话缓存驻留

Windows、CPython 3.14.2。保留 512 条处理后的历史，每条输入为约 40 KiB 的 JSON 工具日志，逐条送入四层 `ContextPipeline.ingest_tool_results`。预热后到最后一条处理完成并回收 Python 垃圾，三个独立进程的 **RSS 增量中位数从 39.36 MiB 降至 2.90 MiB**。前后整段历史的 SHA-256 相同。此回放测量上下文处理进程，未启动桌面窗口。

以下各行独立运行，用 `tracemalloc` 统计释放测试输入后仍驻留的 Python 堆。

| 场景 | 改动前 | 改动后 |
|---|---:|---:|
| 128 条约 128 KiB 工具日志，去除行尾空格 | 32.04 MiB | 3.76 MiB |
| 同批 JSON 工具日志，提取结构骨架 | 16.09 MiB | 3.90 MiB |
| 当前线程估算四份 2 MiB 消息，执行会话清理 | 8.00 MiB | <0.01 MiB |
| 32 个会话各向 SQLite 写入一个约 256 KiB 的压缩差异字段 | 8.27 MiB | 0.02 MiB |

规范化和骨架化各保留最多 512 项、4 MiB 字符串，超预算结果直接返回。token 估算完成即清空临时原文槽，会话切换同步清理调用线程的消息列表与前缀游标。SQLite 的差异写入基线保存最近 32 个会话的行指纹，短于 32 字节的值直接比较，其余用 SHA-256。冷会话下一次保存会重建基线。数据格式保持兼容，回归测试逐项读回完整字段。

桌面端在卡片高度落定后复用 500 ms 滚动空闲定时器复核配额。两个各 20 轮的历史会话（其中一个含 4K PNG）交替切换 10 次，修复前曾留下 16–17 张已渲染卡片，配额为 12。修复后两个独立 Windows Qt 进程均回到 12/12 张。两次主进程 Private Bytes 分别由 782.9、776.4 MiB 到 821.3、821.9 MiB（切换后 5 秒内逐秒采样的最低值），不含 Chromium 子进程。复测命令为 `python -m pytest tests/ui/test_ui_virtmem.py::test_session_switch_memory_rebounds -q -s`。快速切换时曾在改动前后均观察到 Chromium 原生访问冲突；上述测量在每次切换的末张卡片高度落定后采样。

运行 `python -m pytest tests/perf/test_context_memory.py -q -s` 可复测这些场景。单独运行 `test_tool_history_process_rss` 可隔离同一测试进程中其他场景预先分配的内存。

### 2026-11-28 流式正文扫描、卡片占用与隐藏标签面板

Windows、Python 3.14.2、Qt 5。普通文本批次跳过标签注册表查询；跨批标记从最后一个可能的 `<` 续扫，已完成行只保留围栏检测所需的 32 字符尾部。消息卡在第一次需要时才创建拖动占位和交互选项区。隐藏标签面板时暂停状态动画，面板显示且窗口拖动结束后按当前标签状态恢复。

| 同机测量 | 改动前 | 改动后 |
|---|---:|---:|
| 扫描 12,000 批纯中文正文的累计耗时 | 207.21 ms | 18.06 ms |
| 保留 100 张助手卡片的主进程 RSS 增量 | 17.00 MiB | 15.98 MiB |
| 每张卡片的 Qt 子对象数（其中为控件） | 37（16） | 34（14） |
| 面板隐藏后 400 ms 内的状态动画回调 | 5 次 | 0 次 |

扫描与卡片测量取三个独立离屏进程的中位数。每个进程对 32 字符正文的协议扫描重复五次取中位数，再批量创建尚未挂载浏览器的助手卡，运行事件循环 300 ms 并执行 Python 垃圾回收后读取 RSS。100 张卡片的构造耗时中位数为 149 → 165 ms，本次未观察到构造提速。

真实窗口组合回放覆盖短历史、长历史、欢迎页打开历史、布局变化和流式正文。均匀与突发输入下，可见文字增长间隔中位数在改动前后均为 17 ms，P95 分别为 82 → 84 ms、83 → 83 ms。组合回放首次在 Qt 退出清理时出现访问异常，改动前快照与改动后重跑均正常退出。回放入口为 `tests/ui/test_history_first_paint.py`、`tests/ui/test_chat_layout_preview.py`、`tests/perf/test_visible_text_cadence.py`。

### 2026-11-28 空标签页的欢迎视图

切回时，卡片按重新挂载的 viewer 实际高度重置高度记录。否则会话列表高度与回收前相同时，去重会跳过布局更新，把列表裁在起步高度。真窗回归在切走前先显示最近会话，切回后通过 `elementFromPoint` 检查条目中心是否可见、可点击，再验证发出的会话 ID。

内置会话列表隐藏 1.5 秒后归还轻量 WebEngine 视图，切回时用该页最新的会话列表恢复。短时间内切回保留原视图。插件欢迎页自行持有交互状态，不参与此回收。输入框的 15 秒提示轮播随显隐启停。

Windows 真窗，使用 `tests/perf/test_new_tab_baseline.py` 的 `tab_env`。预热首页后依次新建 4 个空页，每次等待欢迎卡和工作目录就绪，再等待 400 ms；最后静置 3 秒。改动前后各一次，5 页时主进程 RSS 为 467.4 → 441.0 MiB，子进程 RSS 之和为 243.1 → 170.0 MiB（子进程求和可能重复计入共享页）。挂在标签页上的欢迎视图和运行中的提示轮播均由 5 个降为 1 个；池中的空闲视图计入内存。新建同步段分别为 51–65 ms 和 52–81 ms，这次采样没有显示创建提速。

`test_hidden_welcome_releases_and_restores_viewer` 验证快速往返、隐藏后释放、提示轮播恢复、后台列表刷新和点击最近会话信号。`tests/ui/test_history_first_paint.py` 验证实际历史会话打开后的首屏。

### 2026-11-28 动态背景和 UI 插件生命周期

Windows、Python 3.14.2，同机对照改动前快照和工作区。8 个区域共用 640×360 素材和 800×450 输出规格，后台预取 3 帧时，实际缩放调用从 24 次降至 3 次。1 个可见、7 个隐藏的订阅者共享素材时，每帧只向可见图层派发。Qt 已销毁而 Python 仍持有引用的最后一个图层，在下个时钟节拍被摘除，解码线程随源回收退出。

对只含空 `register_ui` 的测试插件，首次装载后连续 20 次请求启用，五轮中位数由 37.07 ms 降至 0.68 ms。同目录复用已注册模块，换目录和显式热重载重新注册。测试覆盖首次注册中途失败后移除模块、侧栏项、设置卡，以及修正后重新启用。

主题可见页即时刷新、隐藏页显示时补刷，以及后台对话的现有回归已运行。短对话、长对话和欢迎页打开历史的三组真实窗口回放通过。双标签页测试创建了两个独立窗口，因缺少历史浮动卡跳过了后续隔离断言。本轮测量不含整窗切主题到稳定绘制的耗时。

### 2026-11-28 简洁模式正文收尾

简洁模式正文保留逐帧显示。最近一次入队后连续 110 ms 没有新文字时，按该批入队时的积压量设置最低显示速度，继续遵守视口宽度和高度同步限制。

Windows、Python 3.14.2、真实 WebEngine 窗口。在同一台机器上分别运行三轮 `tests/perf/test_visible_text_cadence.py`（`QT_QPA_PLATFORM=windows`、`DRIFOX_VISIBLE_CADENCE=1`）。收尾从最后一批送入卡片计到浏览器观察到最后一次文字增长，以下为三轮中位数，跨进程对时误差上界为 31–52 ms。

| 输入节奏 | 收尾等待（改动前 → 后） | 文字增长帧间隔 P95（前 → 后） |
|---|---:|---:|
| 每 25 ms 一段 | 272 → 151 ms | 50 → 51 ms |
| 每 200 ms 八段 | 375 → 245 ms | 67 → 67 ms |

两种输入的文字增长帧间隔中位数均保持在 17 ms。回放同时验证末批内容在流结束前完整显示一次，以及向上阅读时滚动位置稳定。

### 2026-11-28 长回复与连续空行

简洁模式识别 Markdown 时，缩进只在当前行内匹配。判断段尾闭合标记时直接比较后缀，未出现空行的文本也可跳过闭合段解析。下表为 Windows、Python 3.14.2 同机测量，取五轮中位数。

| 负载 | 改动前 | 改动后 |
|---|---:|---:|
| 单个简洁模式正文块，连续追加 500 批、每批 204 个中文字，Python 渲染与补丁生成累计耗时 | 515 ms | 113 ms |
| 两段正文间含 1,500 个连续换行，单次 Markdown 判定 | 23.18 ms | 0.035 ms |

500 批回放复用 `tests/widgets/test_block_render_v2_live.py` 的 viewer 和页面替身，每批追加 `"这是连续输出的中文段落。" * 17` 后调用 `_perform_update_v2()`。计时覆盖补丁生成，不含 Chromium 绘制与模型等待。

另用真实 WebEngine 窗口复测 `tests/perf/test_visible_text_cadence.py`。均匀与突发输入下，可见文字刷新间隔中位数前后均为 17 ms，P95 分别维持 50 ms 和 68 ms。Markdown 段尾、工具混排、滚动定位与正文完整性回放通过。

本次相关控件单测 91 项通过、5 项失败。用 `02982b495` 的干净快照运行相同测试文件，89 项通过，相同 5 项失败，涉及简洁模式判定、补丁调用参数和旧渲染路径的源码断言。

### 2026-11-28 消息卡片与流式采样内存

Windows、Python 3.14.2、Qt 离屏，预热后交替保留 60 张带短文本的用户卡与 60 张未创建浏览器的助手卡。三次独立进程测量取中位数，RSS 在构造后运行 300 ms 事件循环并回收 Python 垃圾后采样。

| 指标 | 改动前 | 改动后 |
|---|---:|---:|
| 120 张卡片的进程 RSS 增量 | 26.09 MiB | 22.46 MiB |
| 同批卡片构造耗时 | 215.61 ms | 171.09 ms |
| 未悬停纯文字用户卡的 Qt 子对象数（其中为控件） | 53（21） | 42（16） |

图片条与悬停按钮首次使用时创建。按钮区提前预留宽高，包含插件操作。另测 60 张无插件按钮的用户卡，首次进入的处理耗时中位数 0.31 ms，最大 1.49 ms；逐一进入全部卡片后，同批 RSS 增量为 25.70 MiB。

页脚流式原文采样使用 4 万个互不相同的 64 字符 ASCII 片段，每 200 段读取一次快照。最后一次采样后，tracemalloc 测得该缓冲持有的 Python 堆从 6.78 MiB 降至 2.44 MiB，完整快照仍有 256 万字符。这个指标仅覆盖页脚缓冲，单独计量。

## 三、误区排除记录（防未来重复误判）

### ① 「LRU 回收失效」＝ 测试假象

perf 基线曾判「灌入 120 张、配额 12，淘汰 Δ=0，回收未生效」。#11 追因定论：测试卡的构造**不满足回收链守卫**——只置 `_lazy_rendered=True` 而 viewer 为 None，被 `is_layout_height_settled`（viewer None 必判 False）拦下，`_batch_fully_rendered` 恒 False，候选全空；另有第二拦截点：布局未激活时卡片 geometry 全部重叠 (0,0)，viewport 扫描判「全批可见」→ 全批保护。两处均为测试构造缺陷，**业务代码的回收链本身健康**（守卫放行后 verdict 120→12、空槽 108）。教训：性能测试的「零效果」先查测试自身的采集链路是否可达被测代码，再判业务失效；测试侧修复见 `9e0d533d`。

### ② 「多会话 RSS 无平台期」＝ 分配器表观驻留

#4/#15 曾以「多会话 RSS 线性上升无平台期」推断回收未生效。#15 定论：旧口径卡片全部强引用在裸列表、无容器无回收器，量得的是**零回收上界**；且对象真实释放后 RSS 因分配器表观驻留不即时回落，RSS 单独不能作「未回收」证据。正确口径是「容器内 + 配额回收后稳态」：记账卡数恒 12/配额、稳态 ≈14.5 MB/会话（对照上界 136.9-146.6 MB/会话）。判定依据优先级：存活对象数/记账数 > RSS（RSS 只作辅助）。教训：内存判定必须区分「对象是否被引用」「C++ 是否析构」「RSS 是否回落」三层口径；修复见 `9e0d533d`。

### ③ 「send 尖峰 ≠ tiktoken」＝ provider 插件惰性 import + AST 审计

首次发送实测 96~108ms 尖峰，直觉归因 tiktoken 编码。事实：本机未装 tiktoken；真凶是 `resolve_context_limit` 链路的 provider 插件模块惰性加载 + AST 审计 + profile 缓存冷启动。E5 预热实验实证：后台预热一次后降至 47.7ms，已落地（`0c3fe727`，daemon 线程、不改启动时序）。教训：尖峰归因先查「首次调用独有的冷启动路径」（惰性 import/缓存构建），而非默认怀疑热点常客。

## 四、遗留与后续

### 方案 α 窗口语义（E12 落定的持久化语义，动 save 链前必读）

流式期间的 blob **自含全量字段（不剥离）**——流式拍（尾条 `_partial`）跳过 extract + write_extras，整拍直接全量直存；崩溃窗口上限 = 一个流式拍周期（25s partial flush 间隔），窗口内强退恢复**零丢失为结构保证**。落定拍（finish）自然恢复轻量 blob（剥离语义回归）。任何未来动 save 链的改动必须维持这条不变式：**流式拍全量、落定拍轻量**，破坏它等于打开崩溃丢失窗口。实施见 `5f6b25e7`。
