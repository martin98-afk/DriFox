# 2026-07-25

## 语音输入可行性调研（DriFox）
- 用户（内部开发者）问 DriFox 能否加语音输入 → 结论：**能，但需从 0 建"采集 + STT + UI"三块**。
- 桌面端现状：输入区 `app/widgets/bottom_input_area.py` 的 `SendableTextEdit` 纯文本；`pyproject.toml` 无音频依赖。
- 网关层**已有 inbound voice 半套**：`wecom`/`telegram`/`dingtalk` 适配器接收平台语音并提取转写文本。
- 推荐的零依赖落地路径：`QAudioInput` 录音 → 复用 `openai` 依赖调 Whisper，或接腾讯云 ASR（方言/说话人分离更好）。

## WorkBuddy 语音输入实现（官方文档 + 第三方）
- 交互：输入栏右侧麦克风按钮，按住录音、松手自动发送，首次需授权麦克风。
- 引擎：腾讯云 ASR（Transformer 端到端、中英粤、噪声抑制、说话人分离），官方文档未点名引擎，第三方文章证实。
- 跨渠道：绑定企微/微信后，发语音自动收到→转文字→执行任务（= 网关 inbound voice 模式）。
- 与 DriFox 对照：WorkBuddy 客户端三块正是 DriFox 缺的部分；DriFox 网关半套已存在，可直接照搬其设计。
