# 2026-07-14

## 修复：toggle-window 命令导致启动崩溃（段错误）

**症状**：git 增加 `toggle-window` 命令后 app 无法启动，日志停在 `register_all_commands` 后直接退回命令行，无 Python traceback。

**根因**：`app/main_widget.py` 的 `_register_command_shortcuts` 中新建 `QShortcut` 时写成
`QShortcut(QKeySequence(...), self, None, None, context)` —— 给 PyQt5 的 `QShortcut` 传了 **5 个位置参数**。
PyQt5 `QShortcut` 构造签名只有 4 个（`key, parent, receiver, context`），第 5 个位置参数被错误解析为原生层非法参数，导致**原生段错误（进程静默死亡）**。该方法在 `OpenAIChatToolWindow.__init__`（→ `_init_builtin_commands` → `_register_command_shortcuts`）中执行，构造即崩。

**验证**：沙箱内用 `QApplication`+`QShortcut(5参数)` 实测进程在 QApplication 之后直接死亡、无任何 Python 异常分支，确认是原生崩溃。

**修复**：改回 2 参数构造 + `setContext()`（与原代码及代码库其它 QShortcut 用法一致）：
```python
qs = QShortcut(QKeySequence(cmd_def.shortcut), self)
qs.setContext(context)   # context = Qt.ApplicationShortcut / Qt.WindowShortcut
```
`py_compile` 通过。

**注意**：沙箱环境无法跑真实 GUI（Qt 初始化会访问 NVIDIA 被权限拦截），未做完整启动验证；但崩溃机制已通过隔离复现确认，修复与代码库既有模式一致。

## toggle-window 设计要点
- `Ctrl+Shift+D` 设为 `ApplicationShortcut`，窗口隐藏（hide）后只要 app 仍在前台有焦点即可再次触发显示。
- `_handle_toggle_window_command` 用 `self.window()` 取顶层 `ToolPopupDialog`，`isVisible()` 时 `hide()`，否则 `show()+activateWindow()+raise_()`。
- 局限：`ApplicationShortcut` 非全局热键，若用户 Alt-Tab 切走失去焦点则快捷键不触发；如需"从任何窗口唤醒"需改用系统级热键（win32 `RegisterHotKey` 或键盘钩子）。
