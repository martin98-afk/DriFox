# 2026-07-15

## Gemini thought_signature 适配修复（工具调用 400 错误）

**问题**：DriFox 用 Gemini 2.5+/3 模型做多轮工具调用时，回传历史报 400：
`Function call is missing a thought_signature in functionCall parts`。

**根因**：Gemini 在 functionCall 响应里附带 `thought_signature`（思考签名），
多轮回传时必须原样带回。OpenAI 兼容端点的字段位置是
`tool_calls[i].extra_content.google.thought_signature`。原代码在两处丢失该字段：
1. 解析流式响应时只存 name/arguments；
2. `to_api_message` 原样把残缺 tool_calls 发出去；且 `normalize_tool_call` 把未知字段剥掉。

**修复**（已验证，单元测试全过）：
- `app/core/message_content.py`：
  - `normalize_tool_call` 保留 `thought_signature`（历史存档/加载也走这里）。
  - 新增 `_build_api_tool_call` + `GEMINI_DUMMY_THOUGHT_SIGNATURE="skip_thought_signature_validator"`。
  - `to_api_message`/`messages_to_api` 新增 `is_gemini` 参数：内部带真实签名→注入真实；
    缺签名且 is_gemini→用官方占位串兜底；非 Gemini→不注入。
- `app/core/workers/chat_worker.py`：
  - 新增 `_extract_thought_signature`（读 delta.extra_content）与 `_is_gemini_model`。
  - `_process_response` 流式循环捕获签名到 buffer 与 `_current_tool_calls`。
  - `tool_call_map` 落盘、post-loop 兜底创建均透传 `thought_signature`。
  - 9 处 `messages_to_api`/`to_api_message` 调用点传入 `is_gemini=self._is_gemini_model()`。

**关键验证事实**：
- openai SDK v2.44.0 BaseModel `extra='allow'`，实测实测能把 `extra_content.google.thought_signature` 原样发往 Gemini，且能解析响应里的 `extra_content`。
- 官方占位串两个：`skip_thought_signature_validator` / `context_engineering_is_the_way_to_go`。
- 并行调用仅首个 functionCall 带签名；顺序多步各带各自签名，需全部回传。

**注意**：subagent_worker（SubAgentExecutor，独立 QThread）未继承 OpenAIChatWorker，
仅用 to_api_message 处理 tool 结果；若子智能体用 Gemini 做工具调用需单独核查。

## UI 显示流畅性优化（消除卡顿）

**目标**：極緻優化聊天 UI 的顯示流暢性，各環節零卡頓。

**根因与修复**（均为用户可见卡顿源）：
1. **流式动画边框整卡重绘（最严重）**：`MessageCard.paintEvent` 每 50ms 用 `self.update()`
   重绘整张卡片（含 `QWebEngineView` 子控件），导致流式聊天时持续卡顿。
   → 新增 `_AnimBorderOverlay` 独立透明浮层（鼠标穿透）+ 模块级 `_draw_streaming_border` 辅助函数，
   把 20fps 动画收敛为「只重绘边框浮层」；`_update_anim`/`start_streaming_anim`/`start_retry_anim` 等
   改为只 `update()` 浮层。卡片 `paintEvent` 仅保留静态侧边条。
2. **主线程同步 HTTP（冻结 UI）**：`balance_display.py` 的余额查询 `requests.get`（最长 10s）、
   `history_card.py` 的 URL 导入 `requests.get`（最长 30s）均在主线程同步执行。
   → 改为 `QThread` 后台请求 + 信号回主线程（`_BalanceFetchThread` / `_UrlImportThread`），
   余额结果用 `_current_provider` 校验过期。
3. **auto_loop 强制同步重绘**：`append_log`/`update_log`/`update_tokens` 每事件 `repaint()`。
   → 改为 `update()`（由 Qt 合并到下一帧）。
4. **重试状态栏每 200ms 重复 `setStyleSheet`**：样式构造时已设一次，热路径冗余重解析。
   → `_update_retry_status_bar` 移除 4 处 `setStyleSheet`，仅更新文本/icon。

**额外修复（阻塞启动的预存语法错误）**：全仓多处 Python 2 风格 `except A, B:`
（`message_card.py`×2、`main_widget.py`×10、`agent.py`×3、`history_card.py`×2、`share_card.py`×1）。
这些在 Python 3 下是 SyntaxError，会导致模块无法导入、应用直接崩溃。
→ 统一改为 `except (A, B):`。不修则 UI 根本无法启动。

**验证**：`python -m py_compile` 全部通过；`ruff check` 全部通过。

**关键文件**：`app/widgets/message_card.py`、`app/widgets/balance_display.py`、
`app/widgets/cards/settings/history_card.py`、`app/widgets/cards/settings/auto_loop_card.py`、
`app/main_widget.py`、`app/core/agent.py`、`app/widgets/cards/floating/share_card.py`。
