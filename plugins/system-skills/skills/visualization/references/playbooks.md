# 场景配方（Playbooks）

命中复合场景时按配方组合产物，不现场即兴。每个配方 = 触发信号 + 产物序列 + 衔接要点 + 降级路线。模板代码从 templates.md 取。

## 配方总表

| 配方 | 触发信号 | 产物序列（按输出顺序） |
|------|---------|----------------------|
| 监控总览 | 「总结指标」「压测结果」「服务状态」「监控数据」 | 指标卡组 → 趋势图 → 状态徽章/gauge → markdown 明细表 |
| 选型报告 | 「A vs B」「怎么选」「哪个好」 | 对比卡 → radar → 决策矩阵/quadrantChart → 结论+追问入口 |
| 性能排查 | 「变慢了」「耗时在哪」「瓶颈定位」 | 指标卡组 → 瀑布分解 → 因果流程图 → checklist 建议 |
| 数据周报 | 「周报」「本周数据」「环比」 | 指标卡组 → 趋势图 → 占比/treemap → markdown 明细表 |

指标卡组永远放第一个可视化位：先给结论数值，再给过程与结构。

## 监控总览

1. **指标卡组**（4-6 张）：核心数值 + 环比箭头（▲▼ + `--success`/`--danger`），异常项卡加 `border:1px solid var(--danger)`。
2. **echarts 趋势图**：时间序列主指标，markLine 标基线或阈值。
3. **状态徽章组或 gauge**：异常项聚焦，≤2 个 gauge 并排（容器 400px 高限制）。
4. **markdown 明细表**（正文，不进 widget）。

衔接：卡组后一句话点出异常项引出趋势图（「瓶颈集中在下午时段，看这段曲线」）。

降级：缺时间序列 → 趋势图降为指标卡 + sparkline；缺阈值 → 去 markLine。

## 选型报告

1. **对比卡并排**（2-4 方案）：推荐方案 accent 边框 + 徽章，每卡一句核心差异。
2. **radar**：3-8 维量化对比，维度直接取对比卡要点（延迟/吞吐/成本/生态…），系列 ≤3。
3. **quadrantChart 或 SVG 决策矩阵**：典型使用场景定位（「什么团队选什么」）。
4. **结论一句 + `context-tag[data-type="ask"]`**：追问入口（「展开讲讲方案 B 的持久化」）。

衔接：卡讲定性差异 → radar 讲量化差距 → 矩阵讲场景匹配，文字在各图之间串场。

降级：维度数据缺失 → radar 降为对比卡加粗差异行；quadrantChart 渲染失败 → SVG 决策矩阵。

## 性能排查

1. **指标卡组**：前后对比或基线对比（当前值 vs 基线值 + 偏差%）。
2. **瀑布分解**（echarts 堆叠 bar 模拟）：透明垫底段 + 耗时段，每行一个环节，markLine 标预算线。
3. **SVG 因果流程图**（≤5 节点）：瓶颈定位链（请求 → 网关 5ms → 服务 210ms ← DB 查询 180ms）。
4. **checklist**（templates.md 纵向变体）：修复建议按收益排序。

衔接：瀑布图定位到段（「90% 耗时在 DB 查询」），流程图解释为什么慢。

降级：缺分段时间 → 瀑布图降为指标卡组（各环节均值）。

## 数据周报

1. **指标卡组**：本周值 + 环比百分比。
2. **echarts 趋势**：7 日或 4 周序列。
3. **treemap 或占比图**：构成变化（「新模块占了 30% 增量」）。
4. **markdown 明细表**（正文）。

衔接：卡组给结论，趋势给过程，占比给结构，明细表兜底。

降级：无构成数据 → 跳过第 3 步，不硬凑图。

## 多图叙事规范

- 复杂主题拆多张小图，不塞一张密图；每张图前一两句话说明它展示什么、与上一张的关系。
- 可视化块放回答**后半段**（流式渲染：闭合块才被扫描），文字解读写在图前。
- 图与图之间必须有文字衔接，不连续堆叠。
- 一个配方的可视化块总数 ≤4；超出说明该拆回答或砍次要图。

## 配方不是牢笼

- 用户只要单一产物（「就画个曲线」）→ 直接给单图，不套配方。
- 场景杂交（周报+异常排查）→ 以主场景配方为骨架，借用另一配方的单件。
- 配方与用户显式要求冲突时，用户要求优先。
